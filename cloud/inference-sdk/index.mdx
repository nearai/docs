## Supported APIs

All four languages support these APIs. Chat Completions and Responses also support streaming.

| API | Official SDK integration | Encryption |
| --- | --- | --- |
| Chat Completions | OpenAI JavaScript, Python, and Go | Optional E2EE and OHTTP |
| [Responses](/cloud/inference-sdk/responses) | OpenAI JavaScript, Python, and Go | Optional OHTTP |
| [System One](/cloud/inference-sdk/system-one) | Jev JavaScript and Python | HTTPS |

Rust uses the native NEAR AI client.

## E2EE

End-to-end encryption (E2EE) encrypts supported Chat fields to a verified model key. It is disabled by default and requires a supported NEAR TEE model. Enable it in your language's client options; Responses and System One do not support field E2EE.

## Verification

The SDK verifies Gateway attestation before sending a request and model attestation where supported. After receiving the answer, call `verifyResponse()` or your language's equivalent to verify its signature. For streaming, consume the entire stream first.

Check the returned signature kind:

- `provider_tee`: the verified model signer signed the request and response bytes.
- `gateway`: the verified Gateway signed those bytes. This does not verify model TEE execution.

The language guides show how to verify each response. See [Verification](/cloud/verification) for custom policies and evidence requirements.

## OHTTP

OHTTP adds encryption between the client and the attested Gateway for Chat and Responses. It is optional, disabled by default, and requires Ed25519. See the [JavaScript](/cloud/inference-sdk/javascript#ohttp), [Python](/cloud/inference-sdk/python#ohttp), [Rust](/cloud/inference-sdk/rust#ohttp), or [Go](/cloud/inference-sdk/go#ohttp) configuration.
