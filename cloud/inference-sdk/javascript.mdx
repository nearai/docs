## Install

The SDK is available on [npm](https://www.npmjs.com/package/@nearai/inference-sdk). It requires Node.js 24.22.1 or later for Node usage.

```bash
npm install @nearai/inference-sdk
```

Set your API key in the environment:

```bash
export NEARAI_API_KEY="your-api-key"
```

## Examples

Choose the tab matching your model's API. Save the example as `example.mjs` and run it with `node example.mjs`.

<Tabs>
<Tab title="Chat Completions" id="chat-completions">

Call a supported NEAR TEE model with E2EE enabled, then verify the completion.

```javascript
import { InferenceClient } from '@nearai/inference-sdk/node';

const baseUrl = 'https://cloud-api.near.ai/v1';
const model = 'z-ai/glm-5.3-flash';
const apiKey = process.env.NEARAI_API_KEY;
if (!apiKey) throw new Error('NEARAI_API_KEY is required');

const client = new InferenceClient({
  baseUrl,
  apiKey,
  e2ee: true,
});

const completion = await client.chat.completions.create({
  model,
  messages: [{ role: 'user', content: 'Reply with the word ok.' }],
});

// Verify the response signature before displaying the answer.
const verified = await client.verifyResponse(completion.id);
console.log(`Verified ${verified.signatureKind} response.`);
console.log(completion.choices[0]?.message.content);
```

</Tab>
<Tab title="Responses" id="responses">

Use a Responses model with `store: false` and E2EE disabled. See [Stateless Responses](/cloud/guides/stateless-responses) for conversation history and tool calls.

```javascript
import { InferenceClient } from "@nearai/inference-sdk/node";

const apiKey = process.env.NEARAI_API_KEY;
if (!apiKey) throw new Error("Set NEARAI_API_KEY first.");

const client = new InferenceClient({
  apiKey,
  baseUrl: "https://cloud-api.near.ai/v1",
  e2ee: false,
});

const response = await client.responses.create({
  model: "openai/gpt-6-astra",
  input: "Hello!",
  store: false,
});

// Verify before displaying the answer.
const verified = await client.verifyResponse(response.id);
console.log(response.output_text);
console.log("Verified signer:", verified.signatureKind);
```

<Tab title="Messages" id="messages">

Call an Anthropic model through the Messages API with E2EE disabled.

```javascript
import { InferenceClient } from "@nearai/inference-sdk/node";

const apiKey = process.env.NEARAI_API_KEY;
if (!apiKey) throw new Error("Set NEARAI_API_KEY first.");

const client = new InferenceClient({
  apiKey,
  baseUrl: "https://cloud-api.near.ai/v1",
  e2ee: false,
});

const response = await client.messages.create({
  model: "anthropic/claude-opus-4-6",
  max_tokens: 128,
  messages: [{ role: "user", content: "Hello!" }],
});

// Verify before displaying the answer.
const verified = await client.verifyResponse(response.id);
console.log(response.content
  .filter((block) => block.type === "text")
  .map((block) => block.text)
  .join(""));
console.log("Verified signer:", verified.signatureKind);
```

<Tab title="System One" id="system-one">

Ask Jev a structured question with E2EE and OHTTP disabled.

```javascript
import { InferenceClient } from "@nearai/inference-sdk/node";

const apiKey = process.env.NEARAI_API_KEY;
if (!apiKey) throw new Error("Set NEARAI_API_KEY first.");

const client = new InferenceClient({
  apiKey,
  baseUrl: "https://cloud-api.near.ai/v1",
  e2ee: false,
  ohttp: false,
});

const result = await client.systemone.create({
  model: "typesafe/jev-1.13",
  state: { message: "I was charged twice. Please help." },
  questions: {
    billing: { type: "noul", instructions: "Is this about billing?" },
  },
});

// decisionId is captured from X-Generation-Id.
const verified = await client.verifyResponse(result.decisionId);
console.log(result.data.answers);
console.log("Verified signer:", verified.signatureKind);
```

## E2EE

End-to-end encryption is disabled by default. Set `e2ee: true` to encrypt supported Chat fields to a verified model key and decrypt the response automatically. E2EE requires a supported NEAR TEE model; leave it disabled for other models and APIs.

## Verification

`InferenceClient` verifies the Gateway and every returned NEAR model-attestation candidate before sending an E2EE Chat Completion. Call `verifyResponse()` after a completion to verify its response signature with the request and response bytes captured by the client.

```js
const receipt = await client.verifyResponse(completion.id);
console.log(`Verified ${receipt.signatureKind} response.`);
```

<Note>
  `verifyResponse()` is explicit. For a streaming completion, consume the entire stream first, then call it with the completion ID so the SDK can verify the exact response bytes.
</Note>

### Set a TCB policy

By default, the SDK accepts the Intel TCB statuses `UpToDate` and `OutOfDate`. To require `UpToDate`, apply a policy to both the Gateway and model evidence:

```js
const strict = {
  policy: { acceptedTcbStatuses: ['UpToDate'] },
};

const client = new InferenceClient({
  baseUrl,
  apiKey,
  e2ee: true,
  gatewayVerification: strict,
  modelVerification: strict,
});
```

### Runtime behavior

For Node, import from `@nearai/inference-sdk/node`. It verifies the Gateway TLS peer and binds later requests to the verified Gateway identity. For a browser or application proxy, import from `@nearai/inference-sdk`; browser Fetch cannot read the TLS peer certificate, so that entry point does not perform Gateway TLS binding.

Response records expire after 60 minutes by default. Verify each response before its record expires or you dispose of the client.

See the [SDK overview](/cloud/inference-sdk#verification) for receipt IDs and signature kinds, or [Verification](/cloud/verification) for custom policies.

## OHTTP

Set `ohttp: true` to encapsulate Chat requests and responses with OHTTP. OHTTP uses the SDK's default Ed25519 signing algorithm; it is not compatible with `signingAlgo: 'ecdsa'`.

```js
const client = new InferenceClient({
  baseUrl,
  apiKey,
  e2ee: true,
  ohttp: true,
});
```

The Chat and `verifyResponse()` calls stay the same. Before sending Chat, the SDK verifies the Gateway's signed OHTTP configuration; a missing or invalid configuration blocks the request. OHTTP encapsulates the exchange to the Gateway, while E2EE encrypts supported Chat fields to the verified model key.

<Note>
  OHTTP supports Chat Completions, Responses, and Messages through the Gateway; System One does not support OHTTP. Attestation and signature requests remain regular HTTPS. The configured endpoint or proxy must expose `/ohttp` at the same origin. Authorization and custom headers sent on the outer request, along with the client's network address, are not hidden by OHTTP.
</Note>
