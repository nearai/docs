NEAR AI Cloud gives you access to leading AI models running inside Trusted Execution Environments (TEEs) through a single OpenAI-compatible API. Your prompts and outputs are hardware-encrypted and never accessible to any operator — including NEAR AI. This guide walks you through account setup and your first API call.

## Set Up Your Account

<Steps>
  <Step title="Create your account">
    Go to [cloud.near.ai](https://cloud.near.ai) and sign up. You can use an email address or a supported social login.
  </Step>
  <Step title="Add credits">
    Open the **Credits** section in the dashboard and add funds to your balance. NEAR AI Cloud bills per token consumed — no subscription required.
  </Step>
  <Step title="Generate an API key">
    Open the **API Keys** section, click **Create API Key**, give it a name, and copy the key value.

    <Tip>
      Your API key is shown only once. Store it in a password manager or secret store such as a CI/CD secrets vault. Never commit it to source control.
    </Tip>
  </Step>
</Steps>

## Make Your First API Call

<Note>
  Replace `YOUR_API_KEY` in every example below with the key you generated in the previous step.
</Note>

NEAR AI Cloud offers two connection modes depending on your use case:

- **Gateway** — A single, unified endpoint (`https://cloud-api.near.ai/v1`) that routes requests to any model in the catalog. Use this when you want to switch models without changing your base URL.
- **Direct Completions** — A per-model endpoint (`https://{slug}.completions.near.ai/v1`) that connects you directly to a specific model's TEE cluster. Use this for the lowest possible latency and the strongest isolation guarantees.

<Tabs>
  <Tab title="Gateway">
    Send requests to `https://cloud-api.near.ai/v1` and specify any supported model in the `model` field.

    <Tabs>
      <Tab title="curl">
        ```bash
        curl https://cloud-api.near.ai/v1/chat/completions \
          -H "Authorization: Bearer YOUR_API_KEY" \
          -H "Content-Type: application/json" \
          -d '{
            "model": "zai-org/GLM-5.1-FP8",
            "messages": [
              {
                "role": "user",
                "content": "What is a Trusted Execution Environment?"
              }
            ]
          }'
        ```
      </Tab>
      <Tab title="Python">
        ```python
        from openai import OpenAI

        client = OpenAI(
            base_url="https://cloud-api.near.ai/v1",
            api_key="YOUR_API_KEY",
        )

        response = client.chat.completions.create(
            model="zai-org/GLM-5.1-FP8",
            messages=[
                {
                    "role": "user",
                    "content": "What is a Trusted Execution Environment?",
                }
            ],
        )

        print(response.choices[0].message.content)
        ```
      </Tab>
      <Tab title="JavaScript">
        ```javascript
        import OpenAI from "openai";

        const client = new OpenAI({
          baseURL: "https://cloud-api.near.ai/v1",
          apiKey: "YOUR_API_KEY",
        });

        const response = await client.chat.completions.create({
          model: "zai-org/GLM-5.1-FP8",
          messages: [
            {
              role: "user",
              content: "What is a Trusted Execution Environment?",
            },
          ],
        });

        console.log(response.choices[0].message.content);
        ```
      </Tab>
    </Tabs>
  </Tab>
  <Tab title="Direct Completions">

    <Tabs>

    <Tip>
      Include an `X-Request-Id` header with a UUID you generate to correlate requests in your logs with the attestation record for that inference. This makes it straightforward to verify a specific call later.

## Expected Response

A successful call returns a standard OpenAI-compatible JSON response:

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1714000000,
  "model": "zai-org/GLM-5.1-FP8",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "A Trusted Execution Environment (TEE) is a secure area of a processor that guarantees code and data loaded inside it are protected from the rest of the system..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 14,
    "completion_tokens": 64,
    "total_tokens": 78
  }
}
```

<Note>
  Reasoning models such as GLM-5.1, Qwen3.5-122B, and Kimi K2.6 return an additional `reasoning_content` field alongside the standard `content` field in the response message. This field contains the model's internal chain-of-thought. See [Reasoning Models](/cloud/reasoning-models) for details on how to handle this field in your application.
</Note>

<Tip>
  Because NEAR AI Cloud implements the OpenAI API specification, you can use any existing OpenAI SDK — including the official Python and JavaScript libraries — without modification. Just update `base_url` / `baseURL` to the NEAR AI Cloud endpoint and swap in your API key. See the [OpenAI Compatibility guide](/cloud/guides/openai-compatibility) for the full list of supported endpoints and parameters.
</Tip>
