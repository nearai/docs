Several models on NEAR AI Cloud can **think before they answer** — they work through a problem step by step before producing a final response. This chain-of-thought process is returned in a `reasoning_content` field alongside the usual `content` field, giving you full visibility into the model's reasoning trace. Enabling reasoning typically improves accuracy on complex tasks at the cost of higher token usage and latency.

---

## Overview

Reasoning models operate in two stages:

1. **Thinking stage** — The model's internal reasoning process. Returned in the `reasoning_content` field of the response message (streamed as `delta.reasoning_content` chunks when `stream: true`).
2. **Response stage** — The final answer delivered to the user. Returned in the `content` field as usual.

Reasoning tokens are billed as completion tokens and reported separately in the `usage` object as `reasoning_tokens`, so you can monitor thinking overhead independently of your final answer.

<Tip>
  To check whether a specific model supports reasoning before making a request, call [`GET /v1/models`](https://cloud-api.near.ai/v1/models) and look for `"reasoning"` in the model's `supported_features` array.

  **Known gap:** `Qwen/Qwen3.5-122B-A10B`, `moonshotai/kimi-k2.5`, and `moonshotai/kimi-k2.6` currently reason by default even if their `supported_features` metadata does not yet list the `"reasoning"` flag. Refer to the per-model sections below for the authoritative behavior.
</Tip>

## GLM-5.1

GLM-5.1 (`zai-org/GLM-5.1-FP8`) controls reasoning through the `enable_thinking` key inside `chat_template_kwargs`. **Reasoning is enabled by default** — you do not need to pass any extra parameter to get a reasoning trace.

### Enable Reasoning (explicit)

You can make the intent explicit by setting `"enable_thinking": true`, or simply omit `chat_template_kwargs` entirely:

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "messages": [
      {"role": "user", "content": "How much is 2+2?"}
    ],
    "temperature": 0.4,
    "chat_template_kwargs": {
      "enable_thinking": true
    },
    "stream": true
  }'
```

### Disable Reasoning

To turn off reasoning for GLM-5.1, you **must** explicitly pass `"enable_thinking": false` — omitting the parameter leaves reasoning on:

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "messages": [
      {"role": "user", "content": "How much is 2+2?"}
    ],
    "temperature": 0.4,
    "chat_template_kwargs": {
      "enable_thinking": false
    },
    "stream": true
  }'
```

## Qwen3.5-122B and Qwen3.6-35B

Both `Qwen/Qwen3.5-122B-A10B` and `Qwen/Qwen3.6-35B-A3B-FP8` have reasoning **enabled by default** and automatically include `reasoning_content` in every response. To disable reasoning, set `"enable_thinking": false` in `chat_template_kwargs`:

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "model": "Qwen/Qwen3.5-122B-A10B",
    "messages": [
      {"role": "user", "content": "What is sqrt of 17?"}
    ],
    "chat_template_kwargs": {
      "enable_thinking": false
    },
    "stream": true
  }'
```

The same `"enable_thinking": false` parameter applies to `Qwen/Qwen3.6-35B-A3B-FP8` — just swap the `model` value.

## GPT-OSS-120B

GPT-OSS-120B (`openai/gpt-oss-120b`) **always reasons before answering** — reasoning cannot be disabled. Instead, you control how much thinking budget the model uses via the standard `reasoning_effort` parameter: `"low"`, `"medium"` (default), or `"high"`.

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "model": "openai/gpt-oss-120b",
    "messages": [
      {"role": "user", "content": "How much is 2+2?"}
    ],
    "reasoning_effort": "low",
    "stream": true
  }'
```

Use `"low"` for faster, cheaper responses on simpler tasks; use `"high"` when maximum accuracy is the priority.

## Kimi K2.5 and Kimi K2.6

Kimi K2.5 (`moonshotai/kimi-k2.5`) and Kimi K2.6 (`moonshotai/kimi-k2.6`) have reasoning **enabled by default** and include `reasoning_content` in responses automatically. To disable reasoning, set `"thinking": false` inside `chat_template_kwargs`:

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "model": "moonshotai/kimi-k2.6",
    "messages": [
      {"role": "user", "content": "How much is 2+2?"}
    ],
    "chat_template_kwargs": {
      "thinking": false
    },
    "stream": true
  }'
```

With `"thinking": false` the response contains no reasoning trace and `usage.reasoning_tokens` drops to `0`.

<Warning>
  **`reasoning_effort` is not supported on Kimi models.** Kimi K2.5 and K2.6 silently ignore `reasoning_effort` (and OpenRouter-style `reasoning` request objects) — requests that include them succeed, but the model behaves exactly as if those fields were absent. Reasoning on Kimi is on/off only; there are no effort levels or thinking budgets. Use `chat_template_kwargs.thinking` as shown above.
</Warning>

## Reading Reasoning Output

When reasoning is active, the response includes the thinking trace alongside the final answer:

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "2 + 2 = 4",
      "reasoning_content": "The user asks a simple arithmetic question. 2 plus 2 equals 4. No ambiguity here."
    }
  }],
  "usage": {
    "prompt_tokens": 13,
    "completion_tokens": 81,
    "reasoning_tokens": 73,
    "total_tokens": 94
  }
}
```

- **`reasoning_content`** — the model's full internal thinking trace. When streaming, this arrives as `delta.reasoning_content` chunks before the `delta.content` chunks begin.
- **`usage.reasoning_tokens`** — the number of completion tokens consumed by the thinking stage. These count toward your total usage and are billed at the model's standard completion-token rate.

## When to Use Reasoning

**Reasoning tends to help with:**

- **Complex mathematical problems** — multi-step calculations, proofs, and numerical reasoning that benefit from careful intermediate steps.
- **Logical reasoning** — tasks that require step-by-step deduction or inference across multiple conditions.
- **Code generation** — intricate programming problems where planning the approach before writing code reduces errors.
- **Scientific questions** — problems that require structured analysis or domain knowledge synthesis.

**Reasoning may not be necessary for:**

- **Simple queries** — straightforward questions with direct, unambiguous answers.
- **Latency-critical applications** — reasoning adds time to first token; disable it when speed matters more than accuracy.
- **Cost optimization** — reasoning tokens are billed as completion tokens; disabling thinking on simple tasks meaningfully reduces costs.
