NEAR AI Cloud already protects your inference inside a TEE — your prompts and outputs are encrypted in hardware memory and inaccessible to any operator. End-to-end encryption (E2EE) adds a second cryptographic layer on top of TLS for defense-in-depth: your messages are encrypted on your machine before they leave, and decrypted only inside the specific model's enclave. Even if TLS were compromised at the network boundary, an attacker would only see ciphertext.

## Why Use E2EE

1. **Defense in depth.** Two independent encryption layers (TLS + E2EE) protect your prompts in transit. Compromise of one layer does not expose your plaintext.
2. **Model-specific encryption.** Each message is encrypted to the public key of the specific TEE instance running your model, ensuring no other enclave — and no infrastructure component — can read it.
3. **Cryptographic binding.** The encrypted payload is signed with your Ed25519 client key. The TEE verifies the signature before decrypting, binding the request to your key pair.
4. **Forward secrecy.** A fresh ephemeral X25519 key pair is generated for each request. Compromise of a session key does not expose past or future sessions.

## Encryption Protocol

| Component | Algorithm |
|-----------|-----------|
| Client signing key | Ed25519 |
| Key agreement | X25519 ECDH (ephemeral client key + model static key) |
| Key derivation | HKDF-SHA256 |
| Message encryption | XChaCha20-Poly1305 |
| Wire format | `base64(nonce \|\| ciphertext)` in a JSON string field |

The model's static X25519 public key is retrieved from the API before each session. The client generates an ephemeral X25519 key pair per request, performs ECDH with the model key to derive a shared secret, feeds it through HKDF-SHA256 to produce the encryption key, and then encrypts the message content with XChaCha20-Poly1305.

## Quick Start

The following self-contained Python script demonstrates the full E2EE flow — fetching the model key, encrypting the request, sending it, and decrypting the response.

**Requirements:** `pip install requests PyNaCl cryptography`

```python
import base64
import json
import os
import requests
from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
from cryptography.hazmat.primitives import hashes, serialization
from nacl.signing import SigningKey
from nacl.public import Box, PublicKey as NaclPublicKey
import nacl.utils

API_KEY   = os.environ["NEAR_AI_KEY"]
BASE_URL  = "https://cloud-api.near.ai/v1"
MODEL     = "zai-org/GLM-5.1-FP8"

# 1. Fetch the model's public key
resp = requests.get(
    f"{BASE_URL}/models",
    headers={"Authorization": f"Bearer {API_KEY}"},
)
models = resp.json()["data"]
model_pub_key_b64 = next(
    m["encryption_public_key"] for m in models if m["id"] == MODEL
)
model_pub_key_bytes = base64.b64decode(model_pub_key_b64)

# 2. Generate client signing key (Ed25519)
signing_key = SigningKey.generate()
verify_key_b64 = base64.b64encode(bytes(signing_key.verify_key)).decode()

# 3. Generate ephemeral X25519 key pair for this request
client_priv = X25519PrivateKey.generate()
client_pub  = client_priv.public_key()

# 4. ECDH + HKDF to derive encryption key
model_x25519_pub = X25519PrivateKey.from_private_bytes(
    b"\x00" * 32  # placeholder — real key from model_pub_key_bytes
)
# Actual ECDH:
from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PublicKey
model_pub_obj   = X25519PublicKey.from_public_bytes(model_pub_key_bytes)
shared_secret   = client_priv.exchange(model_pub_obj)
derived_key     = HKDF(
    algorithm=hashes.SHA256(), length=32, salt=None, info=b"nearai-e2ee-v1"
).derive(shared_secret)

# 5. Encrypt message with XChaCha20-Poly1305
from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305
nonce      = os.urandom(24)  # XChaCha20 uses a 24-byte nonce
plaintext  = json.dumps({"role": "user", "content": "What is a TEE?"}).encode()
ciphertext = ChaCha20Poly1305(derived_key).encrypt(nonce, plaintext, None)
encrypted  = base64.b64encode(nonce + ciphertext).decode()

client_pub_b64 = base64.b64encode(
    client_pub.public_bytes(
        serialization.Encoding.Raw, serialization.PublicFormat.Raw
    )
).decode()

# 6. Send the encrypted request
payload = {
    "model": MODEL,
    "messages": [
        {"role": "user", "content": encrypted}
    ],
}
headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json",
    "X-Signing-Algo": "ed25519",
    "X-Client-Pub-Key": verify_key_b64,
    "X-Encryption-Version": "1",
    "X-Model-Pub-Key": model_pub_key_b64,
}

response = requests.post(
    f"{BASE_URL}/chat/completions",
    headers=headers,
    json=payload,
)
data = response.json()

# 7. Decrypt the response
encrypted_reply = data["choices"][0]["message"]["content"]
raw = base64.b64decode(encrypted_reply)
reply_nonce, reply_ct = raw[:24], raw[24:]
plaintext_reply = ChaCha20Poly1305(derived_key).decrypt(reply_nonce, reply_ct, None)
print(json.loads(plaintext_reply)["content"])
```

## Step-by-Step Guide

<Steps>
  <Step title="Get the model's public key">
    Before encrypting, retrieve the model's static encryption public key. This key is served by the TEE and used as the static side of the X25519 ECDH exchange.

    **Gateway:**
    ```bash
    curl https://cloud-api.near.ai/v1/models \
      -H "Authorization: Bearer $NEAR_AI_KEY"
    ```

    **Direct completions:**
    ```bash
    curl https://glm51.completions.near.ai/v1/models \
      -H "Authorization: Bearer $NEAR_AI_KEY"
    ```

    Each model object in the response includes an `encryption_public_key` field (base64-encoded 32-byte X25519 public key).

    **Python:**
    ```python
    import base64, requests

    resp = requests.get(
        "https://cloud-api.near.ai/v1/models",
        headers={"Authorization": f"Bearer {api_key}"},
    )
    models = resp.json()["data"]
    model_pub_key_b64 = next(
        m["encryption_public_key"] for m in models if m["id"] == model_id
    )
    model_pub_key_bytes = base64.b64decode(model_pub_key_b64)
    ```

    **JavaScript:**
    ```javascript
    const resp = await fetch("https://cloud-api.near.ai/v1/models", {
      headers: { Authorization: `Bearer ${apiKey}` },
    });
    const { data: models } = await resp.json();
    const modelPubKeyB64 = models.find((m) => m.id === modelId).encryption_public_key;
    const modelPubKeyBytes = Buffer.from(modelPubKeyB64, "base64");
    ```
  </Step>

  <Step title="Generate your client key pair">
    Generate an Ed25519 signing key pair. The public key is sent in the `X-Client-Pub-Key` header so the TEE can verify request authenticity.

    **Python:**
    ```python
    from nacl.signing import SigningKey
    import base64

    signing_key  = SigningKey.generate()
    verify_key   = signing_key.verify_key
    pub_key_b64  = base64.b64encode(bytes(verify_key)).decode()
    ```

    **JavaScript:**
    ```javascript
    import { generateKeyPair } from "@noble/ed25519";

    const { privateKey, publicKey } = await generateKeyPair();
    const pubKeyB64 = Buffer.from(publicKey).toString("base64");
    ```
  </Step>

  <Step title="Encrypt your messages">
    For each request, generate an ephemeral X25519 key pair, perform ECDH with the model's public key, derive a 32-byte encryption key via HKDF-SHA256, and encrypt each message content string with XChaCha20-Poly1305.

    **Python:**
    ```python
    import base64, json, os
    from cryptography.hazmat.primitives.asymmetric.x25519 import (
        X25519PrivateKey, X25519PublicKey,
    )
    from cryptography.hazmat.primitives.kdf.hkdf import HKDF
    from cryptography.hazmat.primitives import hashes, serialization
    from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

    def encrypt_for_model(plaintext: str, model_pub_key_bytes: bytes):
        # Ephemeral X25519 key pair
        client_priv = X25519PrivateKey.generate()
        client_pub  = client_priv.public_key()

        # ECDH + HKDF
        model_pub   = X25519PublicKey.from_public_bytes(model_pub_key_bytes)
        shared      = client_priv.exchange(model_pub)
        key         = HKDF(
            algorithm=hashes.SHA256(), length=32, salt=None, info=b"nearai-e2ee-v1"
        ).derive(shared)

        # XChaCha20-Poly1305 encryption (24-byte nonce)
        nonce      = os.urandom(24)
        ciphertext = ChaCha20Poly1305(key).encrypt(nonce, plaintext.encode(), None)
        encrypted  = base64.b64encode(nonce + ciphertext).decode()

        client_pub_b64 = base64.b64encode(
            client_pub.public_bytes(
                serialization.Encoding.Raw, serialization.PublicFormat.Raw
            )
        ).decode()

        return encrypted, key, client_pub_b64

    encrypted_content, session_key, client_pub_b64 = encrypt_for_model(
        "What is a Trusted Execution Environment?", model_pub_key_bytes
    )
    ```

    **JavaScript:**
    ```javascript
    import * as x25519 from "@noble/curves/x25519";
    import { hkdf } from "@noble/hashes/hkdf";
    import { sha256 } from "@noble/hashes/sha256";
    import { xchacha20poly1305 } from "@noble/ciphers/chacha";
    import { randomBytes } from "@noble/hashes/utils";

    async function encryptForModel(plaintext, modelPubKeyBytes) {
      // Ephemeral X25519 key pair
      const clientPriv = x25519.utils.randomPrivateKey();
      const clientPub  = x25519.getPublicKey(clientPriv);

      // ECDH + HKDF
      const shared    = x25519.getSharedSecret(clientPriv, modelPubKeyBytes);
      const key       = hkdf(sha256, shared, undefined, "nearai-e2ee-v1", 32);

      // XChaCha20-Poly1305 encryption
      const nonce     = randomBytes(24);
      const cipher    = xchacha20poly1305(key, nonce);
      const encrypted = cipher.encrypt(new TextEncoder().encode(plaintext));

      const combined  = new Uint8Array(nonce.length + encrypted.length);
      combined.set(nonce);
      combined.set(encrypted, nonce.length);

      return {
        encryptedB64:  Buffer.from(combined).toString("base64"),
        sessionKey:    key,
        clientPubB64:  Buffer.from(clientPub).toString("base64"),
      };
    }
    ```
  </Step>

  <Step title="Make the encrypted request">
    Send the encrypted message content in the `messages` array as normal, and include the following required headers:

    | Header | Value | Description |
    |--------|-------|-------------|
    | `X-Signing-Algo` | `ed25519` | Identifies the signing algorithm used |
    | `X-Client-Pub-Key` | base64-encoded Ed25519 public key | Your client's verify key; TEE uses this to authenticate the request |
    | `X-Encryption-Version` | `1` | Protocol version |
    | `X-Model-Pub-Key` | base64-encoded X25519 public key | The model public key you retrieved in Step 1; the TEE validates this matches its own key |
    | `X-Encrypt-All-Fields` | `true` (optional) | Set to encrypt tool call arguments and results in addition to message content (see below) |

    ```bash
    curl https://cloud-api.near.ai/v1/chat/completions \
      -H "Authorization: Bearer $NEAR_AI_KEY" \
      -H "Content-Type: application/json" \
      -H "X-Signing-Algo: ed25519" \
      -H "X-Client-Pub-Key: <base64-encoded-ed25519-pub-key>" \
      -H "X-Encryption-Version: 1" \
      -H "X-Model-Pub-Key: <base64-encoded-x25519-model-pub-key>" \
      -d '{
        "model": "zai-org/GLM-5.1-FP8",
        "messages": [
          {
            "role": "user",
            "content": "<base64(nonce || ciphertext)>"
          }
        ]
      }'
    ```
  </Step>

  <Step title="Decrypt the response">
    The assistant's `content` field in the response will be a base64-encoded `nonce || ciphertext` blob. Decrypt it using the same `session_key` derived in Step 3.

    **Python:**
    ```python
    import base64
    from cryptography.hazmat.primitives.ciphers.aead import ChaCha20Poly1305

    def decrypt_response(encrypted_b64: str, session_key: bytes) -> str:
        raw        = base64.b64decode(encrypted_b64)
        nonce      = raw[:24]
        ciphertext = raw[24:]
        plaintext  = ChaCha20Poly1305(session_key).decrypt(nonce, ciphertext, None)
        return plaintext.decode()

    encrypted_reply = response["choices"][0]["message"]["content"]
    plaintext_reply = decrypt_response(encrypted_reply, session_key)
    print(plaintext_reply)
    ```

    **JavaScript:**
    ```javascript
    import { xchacha20poly1305 } from "@noble/ciphers/chacha";

    function decryptResponse(encryptedB64, sessionKey) {
      const raw        = Buffer.from(encryptedB64, "base64");
      const nonce      = raw.subarray(0, 24);
      const ciphertext = raw.subarray(24);
      const cipher     = xchacha20poly1305(sessionKey, nonce);
      const plaintext  = cipher.decrypt(ciphertext);
      return new TextDecoder().decode(plaintext);
    }

    const encryptedReply = data.choices[0].message.content;
    const plaintextReply = decryptResponse(encryptedReply, sessionKey);
    console.log(plaintextReply);
    ```
  </Step>
</Steps>

## Encrypting All Fields

For requests that include tool calling, set the `X-Encrypt-All-Fields: true` header. This extends encryption to tool call arguments (in assistant messages) and tool results (in tool messages), in addition to the standard message `content` field. Use this when the arguments or outputs of your tool calls contain sensitive data.

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEAR_AI_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Signing-Algo: ed25519" \
  -H "X-Client-Pub-Key: <base64-ed25519-pub-key>" \
  -H "X-Encryption-Version: 1" \
  -H "X-Model-Pub-Key: <base64-x25519-model-pub-key>" \
  -H "X-Encrypt-All-Fields: true" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "messages": [
      { "role": "user", "content": "<encrypted>" }
    ],
    "tools": [...]
  }'
```

## Important Notes

- **Supported endpoints:** E2EE is supported on `POST /v1/chat/completions`. Direct completions endpoints (`https://{slug}.completions.near.ai/v1`) are preferred for E2EE because TLS terminates inside the TEE, providing the strongest end-to-end trust model.
- **Message format:** Each `content` field must be a single base64-encoded string containing `nonce || ciphertext`. Multi-part content arrays are not supported when E2EE is active.
- **Verifying the model key:** To ensure the model public key belongs to a genuine TEE enclave before encrypting, verify the hardware attestation report. See [Verify Your Inference](/cloud/verification/index) for instructions on how to obtain and validate the attestation independently.

<Accordion title="Legacy ECDSA Signing (deprecated)">
  An earlier version of the E2EE protocol used ECDSA (secp256k1) for request signing. This mode is still accepted for backward compatibility but is no longer recommended. New integrations should use Ed25519 (`X-Signing-Algo: ed25519`) as described in this guide. The ECDSA mode uses the same X25519 + XChaCha20-Poly1305 encryption scheme; only the signing algorithm differs.
</Accordion>
