[OpenCode](https://opencode.ai) is an open-source terminal-based AI coding agent. [Goose](https://block.github.io/goose) is Block's open-source AI agent for development automation. Both support custom OpenAI-compatible providers, making it straightforward to route their requests through NEAR AI Cloud's TEE-protected inference.

## OpenCode

### Prerequisites

- OpenCode installed ([opencode.ai](https://opencode.ai))
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)

### Configure

<Steps>
  <Step title="Choose a config file location">
    OpenCode supports both a global config at `~/.config/opencode/opencode.json` and a per-project config at `opencode.json` in your project root. Project configs override global configs.

    For most setups, start with the global config so NEAR AI Cloud is available in every project.
  </Step>
  <Step title="Write the provider configuration">
    Create or edit your `opencode.json` file. Use the `@ai-sdk/openai-compatible` npm package to configure NEAR AI Cloud as a custom provider:

    ```json title="opencode.json (global or project)"
    {
      "$schema": "https://opencode.ai/config.json",
      "provider": {
        "near-ai-cloud": {
          "npm": "@ai-sdk/openai-compatible",
          "name": "NEAR AI Cloud",
          "options": {
            "baseURL": "https://cloud-api.near.ai/v1",
            "apiKey": "{env:NEARAI_API_KEY}"
          },
          "models": {
            "z-ai/glm-5.2": {
              "name": "GLM 5.2"
            },
            "Qwen/Qwen3.5-122B-A10B": {
              "name": "Qwen3.5-122B"
            }
          }
        }
      }
    }
    ```

    The `{env:NEARAI_API_KEY}` placeholder reads the API key from your environment. Set it before running OpenCode:

    ```bash
    export NEARAI_API_KEY="your-near-ai-api-key"
    ```
  </Step>
  <Step title="Add model context limits (optional)">
    OpenCode uses model metadata to manage context. Add `limit` entries when you want to be explicit:

    ```json
    "models": {
      "z-ai/glm-5.2": {
        "name": "GLM 5.2",
        "limit": {
          "context": 131072,
          "output": 8192
        }
      }
    }
    ```

    See [cloud.near.ai/models](https://cloud.near.ai/models) for the context window and output limits for each model.
  </Step>
  <Step title="Select the model in OpenCode">
    Start OpenCode in your project directory:

    ```bash
    opencode
    ```

    Run the `/models` command inside the TUI to open the model picker. Your NEAR AI Cloud models appear under **NEAR AI Cloud**. Select one to activate it for the session.
  </Step>
</Steps>

### Refresh Models

OpenCode reads models from the `models` map in `opencode.json` — it does not call `/v1/models` for custom providers. Add new model entries to the map when you want to use a new NEAR AI Cloud model.

## Goose

### Prerequisites

- Goose installed ([block.github.io/goose](https://block.github.io/goose))
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)

### Configure

<Steps>
  <Step title="Create a declarative provider configuration file">
    Goose supports declarative JSON provider files for OpenAI-compatible APIs. Create a file at `~/.config/goose/providers/near-ai-cloud.json`:

    ```json title="~/.config/goose/providers/near-ai-cloud.json"
    {
      "name": "near-ai-cloud",
      "engine": "openai",
      "host": "https://cloud-api.near.ai/v1",
      "models": [
        {
          "name": "z-ai/glm-5.2",
          "context_window": 131072,
          "supports_tools": true,
          "supports_vision": false
        },
        {
          "name": "Qwen/Qwen3.5-122B-A10B",
          "context_window": 131072,
          "supports_tools": true,
          "supports_vision": false
        }
      ],
      "auth": {
        "type": "header",
        "header_name": "Authorization",
        "header_value": "Bearer ${NEARAI_API_KEY}"
      }
    }
    ```

    Goose automatically discovers provider files placed in `~/.config/goose/providers/`.
  </Step>
  <Step title="Set your API key">
    ```bash
    export NEARAI_API_KEY="your-near-ai-api-key"
    ```

    Add this line to your shell profile (`~/.zshrc`, `~/.bashrc`, etc.) to make it permanent.
  </Step>
  <Step title="Start Goose with the NEAR AI Cloud provider">
    Use environment variables to select the provider and model:

    ```bash
    export GOOSE_PROVIDER="near-ai-cloud"
    export GOOSE_MODEL="z-ai/glm-5.2"
    goose session
    ```

    Or run the interactive configuration:

    ```bash
    goose configure
    ```

    Select **Configure Providers** and choose `near-ai-cloud` from the list to set it as the active provider.
  </Step>
</Steps>

### Refresh Models

Goose reads models from the `models` array in the provider JSON file. Add or update model entries in `~/.config/goose/providers/near-ai-cloud.json` to expose new NEAR AI Cloud models. Check [cloud.near.ai/models](https://cloud.near.ai/models) for current model IDs and capabilities.

## Quick Test (both tools)

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEARAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai/glm-5.2",
    "messages": [
      {
        "role": "user",
        "content": "Reply with one sentence confirming the model is reachable."
      }
    ],
    "max_tokens": 64
  }'
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| OpenCode: model not in `/models` picker | Confirm the model ID in the `models` map matches the exact ID from [cloud.near.ai/models](https://cloud.near.ai/models). |
| OpenCode: `{env:NEARAI_API_KEY}` resolves to empty | Set the environment variable before starting OpenCode: `export NEARAI_API_KEY=...` |
| OpenCode: `baseURL` not accepted | Remove any path suffix — `baseURL` must be `https://cloud-api.near.ai/v1` only. |
| Goose: provider not listed in `goose configure` | Verify the file is at `~/.config/goose/providers/near-ai-cloud.json` and is valid JSON. |
| Goose: `401` error | Check that `${NEARAI_API_KEY}` in the JSON file is set in your shell environment before starting Goose. |
| Goose: `host` field ends with `/chat/completions` | Remove the path — `host` must be `https://cloud-api.near.ai/v1` only. Goose appends the endpoint path itself. |
