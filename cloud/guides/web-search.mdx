NEAR AI Cloud provides built-in web search tools that run entirely server-side. You declare the tool in your request and the model decides when to invoke it — NEAR AI Cloud fetches the results, injects them into the context, and the model uses them to formulate its final answer. You receive a complete, grounded response without writing any tool-dispatch or result-injection code on your end. Web search is billed per search invocation; current pricing is available from `GET /v1/services`.

## Tool Types

NEAR AI Cloud supports two web search tool types with different API compatibility profiles:

| Tool type | Compatible APIs | Description |
|-----------|----------------|-------------|
| `web_context_search` | Responses API | NEAR AI native; injects search results directly into the model context server-side |
| `web_search` | Responses API | OpenAI-compatible web search tool; follows the OpenAI `web_search` specification |

Both tools eliminate client-side tool-handling: unlike standard function calling, you never receive a `finish_reason: "tool_calls"` response that requires a follow-up request. The search loop runs entirely on the server.

## Responses API

Pass `{"type": "web_context_search"}` (or `{"type": "web_search"}`) in the `tools` array of a `POST /v1/responses` request:

```bash
curl https://cloud-api.near.ai/v1/responses \
  -H "Authorization: Bearer $NEAR_AI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "input": "What are the latest developments in confidential computing?",
    "tools": [
      { "type": "web_context_search" }
    ]
  }'
```

The response `output` array contains both the web search call record and the final assistant message:

```json
{
  "id": "resp-abc123",
  "object": "response",
  "model": "zai-org/GLM-5.1-FP8",
  "status": "completed",
  "output": [
    {
      "type": "web_search_call",
      "id": "ws-xyz",
      "status": "completed",
      "action": {
        "type": "search",
        "query": "latest developments confidential computing 2025"
      }
    },
    {
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "output_text",
          "text": "Recent developments in confidential computing include..."
        }
      ]
    }
  ],
  "usage": {
    "input_tokens": 312,
    "output_tokens": 248,
    "total_tokens": 560
  }
}
```

## Chat Completions API

Web search is also available through `POST /v1/chat/completions` using `web_context_search` in the `tools` array. This mode **requires `stream: true`** because search results and the final answer are delivered as a sequence of server-sent event chunks.

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEAR_AI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "messages": [
      {
        "role": "user",
        "content": "What are the latest developments in confidential computing?"
      }
    ],
    "tools": [
      { "type": "web_context_search" }
    ],
    "stream": true
  }'
```

The streaming response contains three types of delta chunks in sequence:

| Delta field | Content |
|-------------|---------|
| `delta.tool_calls` | The search query the model composed before calling the tool |
| `delta.nearai_tool_result` | The search results fetched and injected into the context |
| `delta.content` | The model's final answer, streamed token by token |

You read the full stream to completion and render `delta.content` chunks as the model's response. No follow-up request is needed.

<Note>
  Unlike standard OpenAI function calling, the server handles the entire tool-use loop internally. You will never receive a `finish_reason: "tool_calls"` chunk that requires you to call the tool and send a second request. Simply stream the response to completion and use the `delta.content` chunks as the final answer.
</Note>

## Pricing

Each web search invocation is billed as a platform service usage event at a flat per-search rate. Retrieve current service pricing with:

```bash
curl https://cloud-api.near.ai/v1/services \
  -H "Authorization: Bearer $NEAR_AI_KEY"
```

The response lists all available platform services and their per-unit costs. Search invocations appear in your usage export under `source: "service"` rows.
