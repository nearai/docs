NEAR AI Cloud provides a dedicated reporting token system for automated billing and usage exports. Reporting tokens are separate from your inference API keys — they carry a `usage:read` scope only, are scoped to a single organization, and cannot make inference requests. This separation lets you grant read-only access to a billing system or data pipeline without exposing your inference credentials.

## Reporting Tokens

### Create a Reporting Token

`POST /v1/organizations/{org_id}/reporting-tokens` creates a new reporting token for your organization. You can optionally set a human-readable `name` and an `expires_at` timestamp.

```bash
curl -X POST https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/reporting-tokens \
  -H "Authorization: Bearer $NEAR_AI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "billing-pipeline",
    "expires_at": "2026-01-01T00:00:00Z"
  }'
```

The response includes the full token value in the `token` field:

```json
{
  "id": "rt-abc123",
  "name": "billing-pipeline",
  "organization_id": "org-xyz",
  "created_by_user_id": "user-111",
  "token": "nai_rt_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "token_prefix": "nai_rt_xxxx",
  "scope": "usage:read",
  "created_at": "2025-08-01T12:00:00Z",
  "expires_at": "2026-01-01T00:00:00Z",
  "last_used_at": null
}
```

<Note>
  The `token` field is returned only in this creation response. It is not stored in plaintext and cannot be retrieved again. Copy it to your secrets vault immediately.
</Note>

### List Reporting Tokens

`GET /v1/organizations/{org_id}/reporting-tokens` returns all active (non-revoked) reporting tokens for your organization. The `token` field is not included in list responses — only the `token_prefix` is shown for identification.

```bash
curl https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/reporting-tokens \
  -H "Authorization: Bearer $NEAR_AI_KEY"
```

### Revoke a Reporting Token

`DELETE /v1/organizations/{org_id}/reporting-tokens/{token_id}` permanently revokes a token. Revoked tokens are rejected immediately on subsequent API calls.

```bash
curl -X DELETE \
  https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/reporting-tokens/rt-abc123 \
  -H "Authorization: Bearer $NEAR_AI_KEY"
```

## Authentication

Use your reporting token in the `Authorization` header of export and summary requests, exactly as you would an inference key:

```bash
Authorization: Bearer nai_rt_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Reporting tokens are accepted only on the usage export and summary endpoints. Attempting to call inference endpoints (`/v1/chat/completions`, etc.) with a reporting token returns `403 Forbidden`. Calls to any endpoint with an expired or revoked reporting token return `401 Unauthorized`.

## Export Usage Rows

`GET /v1/organizations/{org_id}/usage/export` returns a cursor-paginated list of individual usage rows for all inference and service events in your organization. Each row is either an **inference row** (a model inference call) or a **service row** (a platform service usage event such as a web search).

```bash
curl "https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/usage/export\
?start_time=2025-07-01T00:00:00Z\
&end_time=2025-07-31T23:59:59Z\
&limit=100" \
  -H "Authorization: Bearer $REPORTING_TOKEN"
```

A sample response page:

### Cursor Pagination

When `next_cursor` is non-null, there are more pages. Pass the value as the `cursor` query parameter in your next request:

```bash
curl "https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/usage/export\
?start_time=2025-07-01T00:00:00Z\
&end_time=2025-07-31T23:59:59Z\
&limit=100\
&cursor=cursor_opaque_string_abc" \
  -H "Authorization: Bearer $REPORTING_TOKEN"
```

Continue fetching pages until `next_cursor` is `null`.

## Summarize Usage

`GET /v1/organizations/{org_id}/usage/summary` returns pre-aggregated totals broken down by workspace, API key, model, and day — useful for dashboards and invoice generation without iterating over every individual row.

```bash
curl "https://cloud-api.near.ai/v1/organizations/YOUR_ORG_ID/usage/summary\
?start_time=2025-07-01T00:00:00Z\
&end_time=2025-07-31T23:59:59Z" \
  -H "Authorization: Bearer $REPORTING_TOKEN"
```

## Filters Reference

Both the export and summary endpoints accept the following query parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `start_time` | RFC3339 string | Inclusive start timestamp. Defaults to 366 days before `end_time`. |
| `end_time` | RFC3339 string | Inclusive end timestamp. Defaults to the request time. |
| `source` | `inference` \| `service` \| `all` | Filter by usage source type. Defaults to `all`. |
| `workspace_id` | UUID | Filter rows to a specific workspace. |
| `api_key_id` | UUID | Filter rows to a specific API key. |
| `model` | string | Filter inference rows by model name (exact match). |
| `inference_type` | string | Filter inference rows by inference type (e.g. `chat`, `completion`). |
| `service_name` | string | Filter service rows by platform service name (e.g. `web_context_search`). |
| `limit` | integer | Maximum rows per page (export only). Defaults to 100; maximum 1000. |
| `cursor` | string | Opaque pagination cursor returned by the previous export page. |

## Cost Units

All cost fields in the API use **nano-USD** (integer):

```
1,000,000,000 nano-USD = $1.00 USD
```

For example, a `total_cost_nano_usd` value of `8,471,000,000` equals $8.47. The `total_cost_usd` field, when present, provides the same value as a decimal string for convenience.

<Note>
  Usage reports contain no sensitive content. The `inference_id` field in inference rows is a correlation identifier — it references a request in the attestation log but does not contain prompt text or model outputs. API key IDs are UUIDs, not key values. Raw API key material never appears in any report.
</Note>
