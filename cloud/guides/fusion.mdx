NEAR AI Fusion lets you fan a single prompt across a panel of models simultaneously, then synthesize their responses with a separate judge model — all in one API call. The result is a single OpenAI-compatible response that reflects the collective output of multiple models, without any client-side orchestration code. Fusion runs entirely server-side inside the TEE infrastructure.

## Request Shapes

You can invoke Fusion in two ways: as a **server tool** in the Responses API `tools` array, or as a **plugin** via the `model` field in the Chat Completions or Responses API.

<Tabs>
  <Tab title="Server Tool (Responses API)">
    Add `{"type": "openrouter:fusion"}` to the `tools` array and provide Fusion parameters in the tool definition. The top-level `model` field sets the model used for final synthesis; the `model` field inside the Fusion parameters sets the judge model for aggregation.

    ```bash
    curl https://cloud-api.near.ai/v1/responses \
      -H "Authorization: Bearer $NEAR_AI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "zai-org/GLM-5.1-FP8",
        "input": "Explain the tradeoffs between homomorphic encryption and TEEs for private AI.",
        "tools": [
          {
            "type": "openrouter:fusion",
            "analysis_models": [
              "Qwen/Qwen3.5-122B-A10B",
              "moonshotai/kimi-k2.6",
              "openai/gpt-oss-120b"
            ],
            "model": "zai-org/GLM-5.1-FP8",
            "max_tool_calls": 1,
            "max_completion_tokens": 2048,
            "temperature": 0.7
          }
        ]
      }'
    ```
  </Tab>
  <Tab title="Plugin (Chat Completions)">
    Set `model` to `openrouter:fusion` and pass Fusion configuration as an additional `nearai_fusion` field in the request body. Use `model` inside `nearai_fusion` to designate the judge model.

    ```bash
    curl https://cloud-api.near.ai/v1/chat/completions \
      -H "Authorization: Bearer $NEAR_AI_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "openrouter:fusion",
        "messages": [
          {
            "role": "user",
            "content": "Explain the tradeoffs between homomorphic encryption and TEEs for private AI."
          }
        ],
        "nearai_fusion": {
          "analysis_models": [
            "Qwen/Qwen3.5-122B-A10B",
            "moonshotai/kimi-k2.6",
            "openai/gpt-oss-120b"
          ],
          "model": "zai-org/GLM-5.1-FP8",
          "max_completion_tokens": 2048,
          "temperature": 0.7
        }
      }'
    ```
  </Tab>
</Tabs>

<Note>
  When using the server tool format, the top-level `model` field determines which model performs the final response synthesis. The `model` field inside the Fusion parameters (or `nearai_fusion` object) designates the judge model responsible for aggregating the panel outputs before synthesis. If you omit the judge `model`, the top-level model also acts as the judge.
</Note>

## Fusion Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `analysis_models` | `string[]` | List of panel models to query in parallel. All listed models receive the same prompt simultaneously. |
| `model` | `string` | Judge model used to aggregate the panel responses before final synthesis. |
| `max_tool_calls` | `integer` | Maximum number of tool-call rounds the judge model may perform during aggregation. |
| `max_completion_tokens` | `integer` | Maximum output tokens for each panel model's individual response. |
| `temperature` | `number` | Sampling temperature applied to panel model calls. |
| `reasoning` | `object` | Reasoning configuration passed to panel models that support chain-of-thought (see [Reasoning Models](/cloud/reasoning-models)). |

## Response Metadata

Fusion appends a `nearai_fusion` object to the response with metadata about the deliberation:

```json
{
  "id": "chatcmpl-fusion-abc123",
  "object": "chat.completion",
  "model": "openrouter:fusion",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "TEEs offer near-native performance with hardware-enforced isolation..."
      },
      "finish_reason": "stop"
    }
  ],
  "nearai_fusion": {
    "status": "completed",
    "forced": false,
    "panel": [
      { "model": "Qwen/Qwen3.5-122B-A10B", "status": "success" },
      { "model": "moonshotai/kimi-k2.6",   "status": "success" },
      { "model": "openai/gpt-oss-120b",    "status": "success" }
    ],
    "judge": "zai-org/GLM-5.1-FP8",
    "aggregate_usage": {
      "prompt_tokens": 4812,
      "completion_tokens": 6234,
      "total_tokens": 11046
    }
  }
}
```

| Field | Description |
|-------|-------------|
| `status` | Overall Fusion status (`completed`, `partial`, `failed`) |
| `forced` | `true` if the final response was forced because the judge exceeded `max_tool_calls` |
| `panel` | Per-model status for each analysis model |
| `judge` | Model identifier of the judge used for aggregation |
| `aggregate_usage` | Combined token counts across all panel and judge calls |

## Web Search with Fusion

You can combine Fusion with `web_context_search` to give panel models access to live web data before deliberating:

```bash
curl https://cloud-api.near.ai/v1/responses \
  -H "Authorization: Bearer $NEAR_AI_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zai-org/GLM-5.1-FP8",
    "input": "What are the latest TEE hardware options for AI inference in 2025?",
    "tools": [
      { "type": "openrouter:fusion",
        "analysis_models": [
          "Qwen/Qwen3.5-122B-A10B",
          "moonshotai/kimi-k2.6"
        ],
        "model": "zai-org/GLM-5.1-FP8",
        "max_tool_calls": 2
      },
      { "type": "web_context_search" }
    ]
  }'
```

When both tools are present, each panel model can invoke `web_context_search` during its analysis phase. The judge then aggregates the web-grounded panel outputs into a single synthesized response.

<Note>
  Raw panel model answers are not returned in the response body by default — only the final synthesized output is included. If a panel model fails (for example, due to a timeout or rate limit), Fusion continues with the remaining panel models and marks the failed model as `"status": "failed"` in the `nearai_fusion.panel` metadata. A fully failed panel results in `"status": "failed"` at the top level.
</Note>
