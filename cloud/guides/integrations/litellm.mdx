[LiteLLM](https://litellm.ai) is an open-source AI gateway that translates calls from 100+ LLM providers into a unified OpenAI-compatible interface. You can add NEAR AI Cloud as a provider in LiteLLM's `config.yaml` so any application behind the LiteLLM proxy can access TEE-protected models without changing its own code.

## Prerequisites

- LiteLLM installed (`pip install litellm[proxy]`)
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)

## Configure

<Steps>
  <Step title="Set the API key environment variable">
    LiteLLM reads provider credentials from environment variables. Export your NEAR AI Cloud key before starting the proxy:

    ```bash
    export NEARAI_API_KEY="your-near-ai-api-key"
    ```

    You can also store it in a `.env` file in the same directory as your `config.yaml`.
  </Step>
  <Step title="Create config.yaml">
    Create a `config.yaml` file that defines NEAR AI Cloud models. Use `openai/` as the model prefix to route through LiteLLM's OpenAI-compatible handler, and set `api_base` to the NEAR AI Cloud gateway:

    ```yaml title="config.yaml"
    model_list:
      - model_name: glm-5.2          # alias exposed to downstream apps
        litellm_params:
          model: openai/z-ai/glm-5.2 # openai/ prefix routes to OpenAI-compatible handler
          api_base: https://cloud-api.near.ai/v1
          api_key: os.environ/NEARAI_API_KEY

      - model_name: qwen3-122b
        litellm_params:
          model: openai/Qwen/Qwen3.5-122B-A10B
          api_base: https://cloud-api.near.ai/v1
          api_key: os.environ/NEARAI_API_KEY

      - model_name: qwen3-35b
        litellm_params:
          model: openai/Qwen/Qwen3.6-35B
          api_base: https://cloud-api.near.ai/v1
          api_key: os.environ/NEARAI_API_KEY
    ```

    The `os.environ/NEARAI_API_KEY` syntax tells LiteLLM to read the value from the `NEARAI_API_KEY` environment variable at runtime — the key never needs to appear in the config file itself.

    <Tip>
      The `api_base` must end with `/v1`. Do **not** append `/chat/completions` — LiteLLM's OpenAI client adds the endpoint path automatically.
    </Tip>
  </Step>
  <Step title="Start the LiteLLM proxy">
    ```bash
    litellm --config config.yaml
    ```

    By default, the proxy listens on `http://0.0.0.0:4000`. You should see a startup message listing the models from your config.
  </Step>
  <Step title="Send requests through the proxy">
    Applications connect to the LiteLLM proxy using the model aliases you defined (e.g. `glm-5.2`, `qwen3-122b`):

    <Tabs>
      <Tab title="curl">
        ```bash
        curl http://0.0.0.0:4000/v1/chat/completions \
          -H "Authorization: Bearer $LITELLM_PROXY_KEY" \
          -H "Content-Type: application/json" \
          -d '{
            "model": "glm-5.2",
            "messages": [
              {
                "role": "user",
                "content": "What is a Trusted Execution Environment?"
              }
            ]
          }'
        ```
      </Tab>
      <Tab title="Python (openai SDK)">
        ```python
        from openai import OpenAI

        client = OpenAI(
            base_url="http://0.0.0.0:4000/v1",
            api_key="your-litellm-proxy-key",  # virtual key if configured, else any string
        )

        response = client.chat.completions.create(
            model="glm-5.2",
            messages=[
                {"role": "user", "content": "What is a Trusted Execution Environment?"}
            ],
        )
        print(response.choices[0].message.content)
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

## Using NEAR AI Cloud Directly (without the proxy)

If you want to call NEAR AI Cloud from a LiteLLM Python script without running the proxy server, pass `api_base` and `api_key` inline:

```python
import litellm

response = litellm.completion(
    model="openai/z-ai/glm-5.2",
    api_key="your-near-ai-api-key",
    api_base="https://cloud-api.near.ai/v1",
    messages=[
        {"role": "user", "content": "What is a Trusted Execution Environment?"}
    ],
)
print(response.choices[0].message.content)
```

## Refresh Models

LiteLLM reads models from `config.yaml` at startup. Add new `model_list` entries and restart the proxy to expose additional NEAR AI Cloud models. Check [cloud.near.ai/models](https://cloud.near.ai/models) for the current list of model IDs.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Not Found Error` when calling the proxy | The `api_base` must include `/v1` — e.g. `https://cloud-api.near.ai/v1`. Missing `/v1` is the most common cause. |
| `401 Unauthorized` from NEAR AI Cloud | Verify `NEARAI_API_KEY` is set in your environment and that `api_key: os.environ/NEARAI_API_KEY` references the correct variable name. |
| Model alias resolves but requests fail | Confirm the `model:` value uses the `openai/` prefix and the exact NEAR AI Cloud model ID — e.g. `openai/z-ai/glm-5.2`, not just `z-ai/glm-5.2`. |
| `api_base` ends with `/chat/completions` | Remove the path suffix. LiteLLM's OpenAI client appends `/chat/completions` automatically. |
| Proxy starts but no models are listed | Check `config.yaml` for YAML syntax errors. Indentation mistakes silently prevent model entries from loading. |
