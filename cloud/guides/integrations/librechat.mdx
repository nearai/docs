[LibreChat](https://librechat.ai) is a self-hosted, multi-user AI chat platform. It supports custom OpenAI-compatible endpoints through the `librechat.yaml` configuration file. You can add NEAR AI Cloud as a custom endpoint so your team can chat with TEE-protected models from the LibreChat UI.

## Prerequisites

- LibreChat installed and running ([librechat.ai/docs/quick_start](https://www.librechat.ai/docs/quick_start))
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)
- Access to edit your `librechat.yaml` file and `.env` file

## Configure

LibreChat uses three files to define a custom endpoint:

1. **`librechat.yaml`** — defines the endpoint name, base URL, models, and settings
2. **`.env`** — stores your API key (referenced by `librechat.yaml`)
3. **`docker-compose.override.yml`** — mounts `librechat.yaml` into the Docker container (Docker installs only)

<Steps>
  <Step title="Mount librechat.yaml (Docker only)">
    If you are running LibreChat in Docker, add a volume mount for `librechat.yaml` in `docker-compose.override.yml`:

    ```yaml title="docker-compose.override.yml"
    services:
      api:
        volumes:
          - type: bind
            source: ./librechat.yaml
            target: /app/librechat.yaml
    ```

    Skip this step if you are running LibreChat locally without Docker.
  </Step>
  <Step title="Add your API key to .env">
    Open your `.env` file and add the NEAR AI Cloud API key:

    ```ini title=".env"
    NEARAI_API_KEY=your-near-ai-api-key
    ```

    This variable is referenced from `librechat.yaml` using the `${NEARAI_API_KEY}` syntax.
  </Step>
  <Step title="Configure the custom endpoint in librechat.yaml">
    Create or edit `librechat.yaml` in the project root. Add a NEAR AI Cloud entry under `endpoints.custom`:

    ```yaml title="librechat.yaml"
    version: 1.3.13
    cache: true

    endpoints:
      custom:
        - name: "NEAR AI Cloud"
          apiKey: "${NEARAI_API_KEY}"
          baseURL: "https://cloud-api.near.ai/v1"
          models:
            default:
              - "z-ai/glm-5.2"
              - "Qwen/Qwen3.5-122B-A10B"
            fetch: true
          titleConvo: true
          titleModel: "z-ai/glm-5.2"
          modelDisplayLabel: "NEAR AI"
    ```

    Key fields:
    - **`baseURL`** — the NEAR AI Cloud gateway endpoint. Do not append `/chat/completions`.
    - **`models.default`** — a seed list of model IDs shown before the fetch runs.
    - **`models.fetch: true`** — instructs LibreChat to call `/v1/models` to auto-populate the full model list.
    - **`titleModel`** — the model used to generate conversation titles.
  </Step>
  <Step title="Restart LibreChat">
    Apply the configuration changes by restarting LibreChat:

    <Tabs>
      <Tab title="Docker">
        ```bash
        docker compose down && docker compose up -d
        ```
      </Tab>
      <Tab title="Local (npm)">
        Stop the running process (`Ctrl+C`) and restart:

        ```bash
        npm run backend
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step title="Verify in the UI">
    Open LibreChat in your browser. Click the endpoint selector in the chat header. **NEAR AI Cloud** should appear in the list. Select it and choose a model to start chatting.

    If the endpoint does not appear, check the server logs:

    ```bash
    docker compose logs api
    ```

    Common issues: YAML indentation errors, missing `.env` variable, or `librechat.yaml` not mounted in Docker.
  </Step>
</Steps>

## Refresh Models

With `models.fetch: true`, LibreChat calls the NEAR AI Cloud `/v1/models` endpoint on startup and populates the model picker automatically. No manual list maintenance is required — new models appear after a restart.

## Quick Test

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEARAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai/glm-5.2",
    "messages": [
      {
        "role": "user",
        "content": "Reply with one sentence confirming the model is reachable."
      }
    ],
    "max_tokens": 64
  }'
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| Endpoint not in selector after restart | Check for YAML syntax errors — a single indentation mistake prevents the file from loading. Validate at [yamllint.com](https://www.yamllint.com). |
| `401 Unauthorized` | Confirm `NEARAI_API_KEY` is set in `.env` and that `apiKey: "${NEARAI_API_KEY}"` in `librechat.yaml` references the correct variable name. |
| Model list is empty | Set `models.fetch: true` and include at least one ID in `models.default` as a fallback. Check that the API key has access to the `/v1/models` endpoint. |
| `baseURL` includes `/chat/completions` | Remove the path — `baseURL` must be `https://cloud-api.near.ai/v1` only. LibreChat appends the chat path itself. |
| Docker: config changes not applied | Verify the `librechat.yaml` volume mount is in `docker-compose.override.yml` and run `docker compose down && docker compose up -d`. |
