[Open WebUI](https://openwebui.com) is a self-hosted AI chat interface that supports any OpenAI-compatible API backend. You can add NEAR AI Cloud as a connection in Open WebUI's Admin Settings so your users can access TEE-protected models from the familiar chat UI.

## Prerequisites

- Open WebUI installed and running ([docs.openwebui.com](https://docs.openwebui.com))
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)
- Admin access to Open WebUI

## Configure

<Steps>
  <Step title="Open Admin Settings">
    Log in to Open WebUI as an admin. Click the ⚙️ gear icon or navigate to **Admin Settings** in the top menu.
  </Step>
  <Step title="Navigate to Connections → OpenAI">
    In the Admin Settings sidebar, select **Connections**. Then click **OpenAI** (this section handles all OpenAI-compatible connections, not just OpenAI itself).
  </Step>
  <Step title="Add a new connection">
    Click **➕ Add Connection**. A form appears with two fields:

    | Field | Value |
    |---|---|
    | **URL** | `https://cloud-api.near.ai/v1` |
    | **API Key** | Your NEAR AI Cloud API key |

    Fill in both fields and click **Save**.
  </Step>
  <Step title="Verify auto-detection">
    After saving, Open WebUI immediately calls the `/v1/models` endpoint to verify the connection and fetch available models. If the connection is healthy, the connection row shows a green status indicator and the NEAR AI Cloud models are automatically added to the model picker.

    <Note>
      Open WebUI verifies connections by calling `/models` with a standard `Bearer` token. NEAR AI Cloud's `/v1/models` endpoint fully supports this. If you see a verification warning, confirm that the URL has no trailing slash and that the API key is correct.
    </Note>
  </Step>
  <Step title="Filter models (optional)">
    If you want to expose only specific NEAR AI Cloud models to your users, expand the connection and find **Model IDs (Filter)**. Type a model ID (e.g. `z-ai/glm-5.2`) and click **+** to add it to the allowlist. Only allowlisted models will appear in the model selector.

    Leave the filter empty to expose all models returned by `/v1/models`.
  </Step>
  <Step title="Select a model and start chatting">
    Close Admin Settings and open a new chat. Click the model selector dropdown at the top of the chat window. NEAR AI Cloud models appear alongside any other connected providers. Select one to start chatting.
  </Step>
</Steps>

## Refresh Models

Open WebUI automatically refreshes the model list from `/v1/models` each time it fetches the connection's models. New NEAR AI Cloud models will appear in the picker without any manual configuration changes.

You can also add a **Prefix ID** to the connection (in Advanced settings) to disambiguate NEAR AI Cloud models from identically named models on other connections — for example, prefix `nearai/` so `glm-5.2` appears as `nearai/glm-5.2`.

## Quick Test

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEARAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai/glm-5.2",
    "messages": [
      {
        "role": "user",
        "content": "Reply with one sentence confirming the model is reachable."
      }
    ],
    "max_tokens": 64
  }'
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| Model list is empty after adding the connection | Check for a trailing slash in the URL — it must be exactly `https://cloud-api.near.ai/v1`. Resave the connection to trigger a fresh `/v1/models` call. |
| `401 Unauthorized` on connection verification | Regenerate your API key at [cloud.near.ai](https://cloud.near.ai) and update the **API Key** field. |
| Connection shows error but chat still works | Some verification checks behave differently for custom providers. If the curl smoke test above succeeds, the connection is functional even if the UI shows a warning. |
| Open WebUI running in Docker, model server unreachable | If NEAR AI Cloud is reachable from your host but not from the Docker container, check your network configuration. Cloud endpoints like `cloud-api.near.ai` should be accessible from within Docker without any special settings. |
| Models from different providers have the same name | Use the **Prefix ID** field to add a unique prefix (e.g. `nearai/`) so NEAR AI Cloud models are distinguishable in the picker. |
