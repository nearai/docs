[Dify](https://dify.ai) is an open-source LLM application development platform for building workflows, chatbots, and agents. It supports OpenAI-compatible providers through the **OpenAI-API-compatible** plugin from the Dify Marketplace. Once configured, you can select NEAR AI Cloud models in any Dify application.

## Prerequisites

- Dify instance running ([dify.ai](https://dify.ai) cloud or self-hosted)
- A NEAR AI Cloud API key from [cloud.near.ai](https://cloud.near.ai)
- Admin access to your Dify workspace

## Configure

<Steps>
  <Step title="Install the OpenAI-API-compatible plugin">
    In Dify, navigate to **Settings → Model Providers** (or click your avatar → **Settings** → **Model Provider** in the sidebar).

    Click **Explore more plugins** or go to the **Marketplace** tab and search for **OpenAI-API-compatible**. Install the plugin published by `langgenius`.

    <Note>
      The OpenAI-API-compatible plugin supports LLMs, text embedding, reranking, speech-to-text, and text-to-speech models through a single OpenAI-compatible API surface.
    </Note>
  </Step>
  <Step title="Add NEAR AI Cloud as a provider">
    After installing the plugin, click **Add Model** (or the **+** icon next to the OpenAI-API-compatible entry in your model list).

    A configuration form appears with these fields:
  </Step>
  <Step title="Fill in the provider form">
    Complete the form with the following values:

    | Field | Value |
    |---|---|
    | **Model Type** | `LLM` |
    | **Model Name** | The model ID, e.g. `z-ai/glm-5.2` |
    | **API Key** | Your NEAR AI Cloud API key |
    | **API Base URL** | `https://cloud-api.near.ai/v1` |
    | **Completion mode** | `Chat` |
    | **Context size** | The model's context window (e.g. `131072`) |
    | **Max tokens** | Maximum output tokens (e.g. `8192`) |
    | **Stream** | Enabled (recommended) |
    | **Vision** | Enable only for multimodal models such as `Qwen/Qwen3-VL-30B-Instruct` |

    <Tip>
      For **LLM/chat models**, use `https://cloud-api.near.ai/v1` as the API Base URL. For non-LLM model types (text embedding, rerank, speech-to-text, TTS), some versions of the plugin append `/v1` internally — if you see a duplicated `/v1/v1` path in error logs, try omitting the `/v1` suffix from the base URL for those model types.
    </Tip>

    Click **Save** to confirm.
  </Step>
  <Step title="Add additional models (optional)">
    Repeat the previous step for each NEAR AI Cloud model you want to use. Each model is configured as a separate entry. Common examples:

    | Model Name | Model ID |
    |---|---|
    | GLM 5.2 | `z-ai/glm-5.2` |
    | Qwen3.5-122B | `Qwen/Qwen3.5-122B-A10B` |
    | GPT-OSS-120B | `openai/gpt-oss-120b` |

    See [cloud.near.ai/models](https://cloud.near.ai/models) for the full list of current model IDs.
  </Step>
  <Step title="Use the model in a Dify application">
    Open or create a Dify application (Chatbot, Chatflow, or Workflow). In the **Orchestrate** view or the model selector panel, click the model dropdown and find your NEAR AI Cloud model under the **OpenAI-API-compatible** provider group. Select it to use it in your application.

    Click **Publish** (or **Run App** for Chatflow) to deploy the application with the selected model.
  </Step>
</Steps>

## Refresh Models

Dify's OpenAI-API-compatible plugin uses a customizable model configuration — each model you want to use must be added individually through the **Add Model** form. Dify does not auto-fetch the NEAR AI Cloud `/v1/models` endpoint for this plugin. Check [cloud.near.ai/models](https://cloud.near.ai/models) for new model IDs and add them manually when needed.

## Quick Test

```bash
curl https://cloud-api.near.ai/v1/chat/completions \
  -H "Authorization: Bearer $NEARAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai/glm-5.2",
    "messages": [
      {
        "role": "user",
        "content": "Reply with one sentence confirming the model is reachable."
      }
    ],
    "max_tokens": 64
  }'
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| Model not appearing in application model selector | Verify the model was saved under **Settings → Model Providers → OpenAI-API-compatible**. Check for typos in the **Model Name** field. |
| `401 Unauthorized` | Re-enter your API key in the model configuration form. Generate a new key at [cloud.near.ai](https://cloud.near.ai) if needed. |
| **API Base URL** includes `/chat/completions` | Remove the path — the URL must be `https://cloud-api.near.ai/v1` only. Dify appends the endpoint path. |
| Duplicated `/v1/v1` path in error logs | For non-LLM model types, try setting **API Base URL** to `https://cloud-api.near.ai` (without `/v1`) and let the plugin append the version prefix. |
| Responses stream but show empty content | Confirm **Stream** is enabled and the **Model Name** exactly matches the model ID returned by the NEAR AI Cloud API. |
