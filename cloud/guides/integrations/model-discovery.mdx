Most OpenAI-compatible tools — Cursor, Cline, Open WebUI, LiteLLM, and many others — call a provider's `/v1/models` endpoint to build their model picker. NEAR AI Cloud exposes a fully OpenAI-compatible models endpoint, so any tool that supports automatic model discovery can fetch the current catalog without you maintaining a static list.

## The Endpoint

```text
GET https://cloud-api.near.ai/v1/models
```

The endpoint requires your NEAR AI Cloud API key in a standard Bearer header and returns a JSON array of model objects following the OpenAI `Model` schema.

```bash
curl https://cloud-api.near.ai/v1/models \
  -H "Authorization: Bearer $NEARAI_API_KEY"
```

A successful response looks like:

```json
{
  "object": "list",
  "data": [
    {
      "id": "z-ai/glm-5.2",
      "object": "model",
      "created": 1714000000,
      "owned_by": "z-ai",
      "context_length": 131072,
      "supported_features": ["tools", "structured_outputs", "reasoning"],
      "supported_parameters": ["temperature", "top_p", "max_tokens", "reasoning_effort"]
    },
    {
      "id": "Qwen/Qwen3.5-122B-A10B",
      "object": "model",
      "created": 1714000000,
      "owned_by": "Qwen",
      "context_length": 131072,
      "supported_features": ["tools", "structured_outputs", "reasoning"]
    }
  ]
}
```

Each object includes NEAR AI-specific extensions such as `context_length`, `supported_features`, and `supported_parameters` that tools can use for smarter model configuration. See [Models](/cloud/models) for the full field reference.

## How Tools Use the Endpoint

When you set `https://cloud-api.near.ai/v1` as the base URL and supply your API key, a compatible tool will:

1. Append `/models` to the base URL and send a `GET` request with your `Authorization: Bearer <key>` header.
2. Parse the returned model IDs into its model picker or dropdown.
3. Refresh the list whenever you trigger a model reload (or on startup, depending on the tool).

This means your model picker always reflects whatever NEAR AI Cloud currently offers — no manual updates needed when new models are added.

## Configuring Tools to Use Auto-Discovery

The base URL to configure in any tool is:

```text
https://cloud-api.near.ai/v1
```

Do **not** append `/chat/completions` or `/models` to this value. The tool constructs the full request paths itself. Setting the base URL correctly is the only step required to enable auto-discovery.

Each integration guide in this section walks through the exact UI fields or config keys for that tool:

- [Cursor](/cloud/guides/integrations/cursor) — **OpenAI Compatible → API Base URL**
- [Continue](/cloud/guides/integrations/continue) — `apiBase` in `config.yaml`
- [Cline / Roo / Kilo](/cloud/guides/integrations/cline-roo-kilo) — **Base URL** in the OpenAI Compatible provider settings
- [Aider / Zed](/cloud/guides/integrations/aider-zed) — `OPENAI_API_BASE` env var (Aider) or `api_url` in `settings.json` (Zed)
- [Open WebUI](/cloud/guides/integrations/open-webui) — **URL** field in Admin Settings → Connections
- [LiteLLM](/cloud/guides/integrations/litellm) — `api_base` in `config.yaml`
- [LibreChat](/cloud/guides/integrations/librechat) — `baseURL` in `librechat.yaml`
- [Dify](/cloud/guides/integrations/dify) — **API Base URL** in the model provider form

## Troubleshooting Model Discovery

| Symptom | Fix |
|---|---|
| Model list is empty after saving credentials | Verify the base URL is exactly `https://cloud-api.near.ai/v1` with no trailing slash and no path suffix. |
| `401 Unauthorized` when fetching models | Check that the API key is valid and has not expired. Generate a new key at [cloud.near.ai](https://cloud.near.ai). |
| Tool shows models but requests fail | Confirm the model ID from the picker matches one returned by the `/v1/models` endpoint exactly, including the `owner/model-name` format. |
| Tool auto-discovery is disabled or unsupported | Enter model IDs manually using the IDs returned by the `/v1/models` endpoint. See the [Models catalog](/cloud/models) for a browsable list. |
