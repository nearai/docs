<Warning>
  Direct model endpoint verification is experimental. For new integrations and production verification workflows, use the [NEAR AI Cloud Gateway verification flow](/cloud/verification).
</Warning>

Use these checks to inspect the evidence returned by a direct request or bound to an open TLS connection. A direct response-signature lookup can return `404`; treat that signature as unavailable.

## Available experimental checks

<CardGroup cols={2}>
  <Card title="Model attestation report" icon="brain-circuit" href="/cloud/verification/direct/model-attestation">

## Start with model attestation

1. Generate a fresh nonce for this verification attempt.
2. Request a fresh report from the same direct endpoint your application uses for inference.
3. Verify the model's hardware attestation and apply your acceptance policy.
4. Add TLS, response-signature, or image-provenance checks only for the direct request under inspection.

Start with [Model attestation report](/cloud/verification/direct/model-attestation).
